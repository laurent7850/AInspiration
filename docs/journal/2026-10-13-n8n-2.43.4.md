## Fait

- **n8n monté de 2.40.5 (22/09) à 2.43.4** sur le VPS, à la demande de Laurent.
- **Cible choisie par empreinte, pas par étiquette** : `stable` et `latest` sur Docker Hub
  pointaient tous deux sur `c34ee9107a42`, qui est l'étiquette `2.43.4` (publiée le 12/10).
  `next` était déjà la 2.44.0 : pas prise. Aucun changement cassant publié entre 2.41 et
  2.43 (notes de version GitHub et docs n8n relues).
- **Sauvegarde à chaud avant bascule** : `/usr/local/bin/n8n-backup.sh` →
  `n8n_20261013_110128.tar.gz` (24 Mo, `database.sqlite` 155 Mo + `config` avec la clé de
  chiffrement). La chute de taille depuis le 11/10 (170 Mo → 24 Mo) n'est pas une perte : la
  purge des exécutions à 14 jours fait son travail, 310 exécutions en base (du 30/09 au
  13/10), 42 workflows, 27 credentials — archive listée et vérifiée.
- Déroulé : `docker pull n8nio/n8n:2.43.4` en `nohup` (les connexions SSH coupent sur les
  commandes longues), compose `/root/docker-compose.yml` sauvegardé en
  `docker-compose.yml.bak-20261013-n8n-2.43.4`, étiquette changée, `docker compose up -d
  n8n`. **30 migrations sur 30** terminées (credentials, agents, rôles, publication),
  « Editor is now accessible », zéro redémarrage, `/healthz` 200, **42 workflows actifs
  avant comme après**, API publique opérationnelle (le MCP liste les workflows).
- Image 2.40.5 conservée sur le VPS pour un retour arrière rapide (restaurer le `.bak` du
  compose + `docker compose up -d n8n`), à supprimer dans une semaine.

## Cassé

- Rien. Un avertissement au boot, « Failed to start Python task runner … Python 3 is
  missing » : sans objet, aucun des 42 workflows n'a de nœud Code en Python (vérifié dans
  l'export). Il était probablement déjà là en 2.40.5.

## Reste

- `docker rmi n8nio/n8n:2.40.5` après une semaine sans incident.
